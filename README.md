# knfsolv

A Rust Kniffel engine with desktop and terminal score sheets. Enter every player's sheet, the active player, current dice, and rerolls remaining. Get advice for retaining dice or scoring a category, with alternatives and estimated winning chances.

Uses **standard Kniffel only**, following the included Schmidt rulebook and the explicit conventions in [docs/rules.md](docs/rules.md).

## Run

### Graphical desktop app

```sh
cargo run --release -- gui
cargo run --release -- gui --load examples/middle.json
cargo run --release -- gui --players 4
```

The Rust desktop interface uses [egui/eframe](https://docs.rs/eframe/0.34.3/eframe/) with native Wayland/X11 support on Linux. It needs a graphical desktop and an OpenGL-capable driver. The GUI is included in the default build; existing CLI/TUI behavior is unchanged.

- Start with **Local game**, **Play computer**, **Analyze a position**, or **Load session**. Local setup offers **2–8 players** (default two), names, a starting player, and **Physical dice / Digital dice**. Turns follow the listed order, wrapping around from the starting player. `--players` preselects the setup count when no preferences have been saved; `--load` opens a session directly. The position editor supports 1–8 players.
- **Play computer** creates one human and one computer. Choose names, who starts, your dice source, and **Easy / Standard / Strong / Custom search**. Computer dice are always generated by the app. **Pause computer / Resume computer** and **Fast play** stay in the toolbar; normal play shows each choice with a 400 ms delay. Undo returns to your preceding decision and removes subsequent computer actions.
- Gameplay, the face picker, and engine cards share rounded pip dice. **Keep**, **Locked**, and **Advice** labels distinguish their states; outlines show correction selection and keyboard focus. The grouped toolbar and score panels use the same theme-aware styling.
- Enter five physical dice with **five palette clicks or keys 1–6**. The roll completes automatically. Slots keep their entered order.
- Click a die to toggle **Keep** and select it for correction; use the shared palette or a number key to change the selected face. **Backspace / Clear** clears the last editable slot. Corrections to a completed roll commit after 250 ms without further edits; scoring and advice are disabled while corrections are pending. **Undo** resets unfinished entry, or undoes a whole completed roll/correction.
- Click the large **Reroll N dice** button, then enter only the newly rolled faces. Retained dice stay locked in their original slots. For digital dice, choose **Digital dice** during setup and click **Roll** when ready. Settings can also change the dice source. Digital rerolls generate the unkept dice immediately; starting a human turn never rolls automatically.
- Available cells show prospective points. **Click a score once to end the turn**, including a zero. Filled cells are read-only during normal play; rows stay in place as they fill. Use **Undo / Redo** in the toolbar to restore a decision.
- Advice starts automatically after a complete, valid roll and continuously refines for the active human. **Pause analysis / Resume analysis** preserves accumulated evidence. Choose **Limited** to stop at the saved time/sample limits (defaults: two seconds / 20,000 games; three seconds in the browser), or **Continuous** to keep refining the same estimate. After a limited analysis stops, **Compute longer** continues the same search for the current position. With a single player, advice maximizes the expected final score. Depth and node controls are in **Settings → Engine**, also opened directly by **Engine settings** in the advice header. **Play suggestion** executes its scoring or reroll action immediately. **★ Advice** marks recommended dice or categories independently of your Keep selection. **Play suggestion** executes the recommended move; **Play this move** executes any alternative, including expanded moves. Scoring commits immediately, digital rerolls generate replacements, and physical rerolls lock the indicated keeps while you enter new faces. A bordered **Recommended** move card and three alternatives show retained dice or immediate scoring points, **Win / Tie / Lose**, and **expected final game score**. **Show all moves / Show fewer** expands the remaining moves. Win means outright first; Tie means tied for first; Lose covers the rest (hover for definitions). Missing statistics show **Estimating…**. Status, confidence, and provisional-baseline labeling remain visible. **Analysis details** starts collapsed and contains selection reasoning, model assumptions, objective-specific intervals, paired comparisons, sample counts, budgets, and stop reasons. Both disclosures stay open across continuous updates.
- **Analyze a position** infers the next player from filled-category counts and turn order (zero counts as filled). With only Player 1’s Three of a Kind filled, it forecasts **Player 2** automatically. Equal counts select the first seat in the configured order. Inconsistent intermediate edits suspend analysis until corrected; completed sheets show final results.
- The **Before-roll forecast** shows Win/Tie/Lose chances and expected final score averaged over future rolls. Dice entry is optional: partial entry suspends analysis, five dice switch to move advice, and **Analyze before first roll** discards dice to return to forecasting. Entered dice belong to the rolling player: they stay through edits as long as that player still rolls (for example, a forgotten entry of another player) and are cleared when an edit hands the roll to someone else. In the editor, **Apply suggestion** / **Apply this move** play the advice into the position: a reroll locks the kept dice so only the new faces need entering, and a score is written before the next player is up. Each edit and inferred turn is one Undo/Redo step. Global engine budgets, Limited/Continuous mode, and pause preference still apply.
- In **Analyze a position**, hover a score cell and scroll up/down through **Open → 0 → legal positive scores**. Click a cell to open the score picker, which offers only that category's legal scores (plus **Open**, **Cross out (0)**, and the current roll's points for the rolling player); one click applies a value. Each changed value is one Undo step; scrolling elsewhere scrolls the sheet. **Settings → Game → Score wheel limits** selects **Stop at ends** (default) or **Wrap around**, remembered globally across restarts. Changing this preference does not change or dirty the position.
- **Settings → Game → Hypothetical position** enables explicit active-player and advice-perspective selection for puzzles. In local/computer games, toolbar **Edit position** still edits history without advancing turns, with gameplay paused. Empty means open; zero means crossed out. **Settings** contains theme, position, model, and computation controls; changing computation settings preserves partial dice entry.
- **File** contains the session-path field, **Save**, **Load session**, and **New game**. It uses the same JSON files as the CLI/TUI. New game returns to setup while preserving the current session; **Return to session** resumes it. Unsaved work prompts when you start a replacement game/editor, load another session, or close. Incomplete drafts cannot be saved: finish them or reset them with Undo. Completed corrections are committed before saving. Loading or starting a new game clears undo/redo history. Digital redo restores the recorded outcome and RNG state. Existing files without desktop metadata open in Edit position; choose **Play** in the mode menu to resume physical play.
- Finished games show every player’s total, upper bonus, extra Kniffel points, and **all tied winners**. **Review score sheets** opens the final sheets; **Undo** restores the last scoring decision. **New game** returns to setup.
- Dice and advice stay visible while the sheets scroll at 800×600 and larger. Wide windows place advice beside play; narrower windows stack it below the dice. Smaller windows scroll the full play area. **Tab / Shift-Tab**, focused-button activation, and standard arrow navigation work; with no widget focused, **Left/Right or h/l** selects a die and **Space** toggles Keep. **Ctrl/Cmd-Z** undoes; **Ctrl/Cmd-Shift-Z** redoes. Dice shortcuts leave text fields alone.

The six-stage [GUI redesign](docs/gui-redesign.md) has reached its release verification checkpoint; see the [checks and limitations](docs/verification.md). Continuous coaching runs on one persistent worker, with provisional baseline advice while samples accumulate. Paused time does not consume the computation budget. Dice, position, and model changes invalidate old advice; incomplete rolls wait. GUI game files preserve position context, gameplay RNG state, and computer difficulty/search configuration; global advice preferences are stored separately; accumulated search evidence stays in memory. Computer play uses the same legal controller commands. Pause, Undo, load, setup navigation, and position/configuration changes cancel old executable results. Search failures use a declared legal baseline with an explanation; cancellation never causes a fallback move. The app uses a path field rather than an operating-system file picker; screen-reader behavior has not been manually audited.

Desktop preferences are remembered automatically in a versioned `preferences.json`: on Linux, `$XDG_CONFIG_HOME/knfsolv/preferences.json` or `~/.config/knfsolv/preferences.json`; on macOS, `~/Library/Application Support/knfsolv/preferences.json`; on Windows, `%APPDATA%/knfsolv/preferences.json`. Theme, global advice settings/model paths, per-seat model defaults, analysis mode/pause, and new-game setup defaults load before analysis starts. Changes save atomically after a 300 ms debounce and pending changes flush on normal exit. Save errors remain visible with **Retry**. Invalid files use defaults with an explanation and stay untouched until a preference changes.

**Settings → Engine** changes advice globally, including when opening older games. These changes do not dirty game saves or enter Undo/Redo. **Settings → Game** edits position context. Opened games retain their players, dice source, and computer configuration. Game progress is still saved manually: preferences contain no position, dice, scores, gameplay RNG, selected perspective, or undo history, and the app does not reopen games automatically. CLI/TUI explicit session settings continue to round-trip as before.

The advice header displays **Tree depth N**, **Tree depth N · validating**, **Exact depth N**, or **Full-game rollouts**; **Preparing…** appears before progress exists. Depth is the deepest explored branch, not a depth solved uniformly across all moves. It counts the analyzed player's decisions from 1 at the root, excluding dice, opponents, and baseline rollout continuation. Validation retains the trained tree depth; pause retains progress, and position/engine changes reset it. An Auto fallback shows its current method and records the incomplete exact attempt in Analysis details. The configured MCTS depth limit remains separately labeled in Engine settings.

### Browser (experimental)

The same interface also runs in a browser via WebAssembly, as the first step toward the [iPhone web app](docs/iphone-web-app-plan.md). It needs the Wasm target and [Trunk](https://trunkrs.dev):

```sh
rustup target add wasm32-unknown-unknown
cd web
trunk serve --release   # http://127.0.0.1:8080
./serve-lan.sh          # https://<lan-ip>:8443 for a phone on the same Wi-Fi
```

Phones need the HTTPS address: iOS 27 runs plain-HTTP pages from LAN addresses without its JavaScript and WebAssembly compiler, which makes the solver about 35 times slower. `serve-lan.sh` creates a self-signed certificate in `web/.tls/`; Safari warns once per certificate, continue with *Details einblenden* → *diese Website besuchen*.

Analysis runs in a Web Worker (`web/src/bin/worker.rs`), so the page stays responsive; the worker restarts by itself after a crash and pauses while the page is hidden. The current position and preferences are saved automatically in browser storage, and the app reopens the last position. Instead of paths, *File* offers *Share position* (share sheet, or a download) and *Open position* (file picker); the files are desktop saves, so positions move between the phone and the desktop app. Safari keeps separate storage for the Home Screen app and for Safari tabs.

Below 600 points wide (phones, narrow windows), the play screen switches to a phone layout: a fixed top bar with the ☰ menu (new position with the same players, new game, appearance, thinking time *Quick* 3 s / *Thorough* 15 s / *No limit*, share and open, advanced settings as a page of their own) and Undo/Redo, then one scrolling page with the dice (roll selector *1./2./3.*, face palette), an advice card (the move in words, chance of winning and expected final score, *Apply*, other moves, status, technical details), and a compact score sheet whose player columns scroll sideways when they do not fit. Touch targets are at least 44 points. The start screen there is a one-page welcome (analyze a position, open a position, local game, game against the computer), and *Analyze a position* asks who is playing: 1–8 players in playing order, with names defaulting to "Me", "Player 2", and so on. *Local game* and *Against the computer* have phone setups as well (players, who starts, real or app dice, the computer's strength); names typed once carry over between the setups, and a finished game shows the standings. *Text size* (Normal / Large) in the ☰ menu scales the interface by 1.25 and is remembered. Headless tests render the phone screens in English and German at 312×675 (a 390-point iPhone with large text), 375×667, 390×844, and 430×932: nothing is cut off at the side, every touch target is at least 44 points, three (at 312) or four player columns fit without sideways scrolling, the dice, advice, and *Apply* are visible without scrolling from 390×844 on, and the score picker and player sheet fit the smallest size.

Test addresses, which are not saved: `?bench` opens a two-player opening in the analyzer, `?endgame` a one-player endgame that is solved exactly, and `?debug` adds worker diagnostics with a button that crashes the worker. `?speed` (or `?speed=<games>`) runs a speed test without the interface: timing checks and a fixed number of solver games in the worker. `cargo run --release -p knfsolv-web -- speed` runs the same test natively for comparison.

For a terminal-only build without graphical dependencies:

```sh
cargo run --release --no-default-features
```

### Terminal interface

```sh
cargo run --release
```

Use a release build for analysis. All dependencies were available locally during development; no model download or precomputation is needed.

Start with **D** to open the visual dice picker. Left/Right or `h/l` selects a die; Up/Down or `k/j` cycles its face. Alternatively, press `1`–`6` to set a face and move to the next die. Enter confirms all five dice; Escape discards changes. Kept dice are locked during reroll entry. Opening the picker on an existing roll corrects the dice without consuming a reroll.

Then press **A** to analyze and **X** to apply advice. A reroll recommendation opens the picker for the actual result. **M** opens a navigable action menu, so common tasks do not require memorizing commands. **W** previews scoring the selected category for the active player; Enter confirms and advances the turn, Escape goes back.

Arrows or Vim `h/j/k/l` navigate the sheet; `g/G` jumps to the first/last category. Enter edits a sheet cell without advancing the turn (`-` or empty = open, `0` = crossed out). **S** saves, **U** undoes, **R** or Ctrl-R redoes. `?` opens help; `j/k` scrolls it, Escape closes it. Page Up/Down or Ctrl-U/D scroll advice. Q quits without autosaving. `:` still opens advanced commands. Player and category numbers in the TUI start at **1**.

Press **B** for computation settings. Up/Down or `k/j` selects time, simulations, nodes, or depth; Enter prompts for a new value. B/Escape closes the panel. Settings are saved with the session, and changing them cancels old analysis. Equivalent commands are `time 5000`, `samples 100000`, `nodes 200000`, and `depth 3`.

Time is in milliseconds (`0` disables the time limit). Simulations and nodes must be positive. MCTS depth counts your decisions, including the current decision: depth `1` searches the next action and uses the baseline thereafter; `0` means unlimited depth and is the default. Opponent moves and dice rolls do not count toward depth. Simulations always finish the game to evaluate the outcome. Depth affects MCTS, including Auto's MCTS fallback; exact search uses time/node budgets and fixed rollout uses time/sample budgets.

For example, load a position and analyze it:

```sh
cargo run --release -- tui --load examples/middle.json
```

For a position entered manually, these TUI commands set player 1's current roll and request advice:

```text
turn 1
perspective 1
dice 1 6 6 6 6 2
analyze
```

Here `dice 1` means **one reroll remains**, followed by the five dice. `roll 6 6 6 6 2` instead enters a real roll in a pending-roll phase and checks retained dice. Use `write 13` to score Chance from known dice, or `record 13 26` to record a player's observed score without entering their dice. Both advance the turn. `extra 2 1` sets player 2's already-earned additional-Kniffel count to one; it is a count, not bonus points.

Use `order 2 1` to make player 2 the first player in a two-player match. An ordinary position must have filled-cell counts consistent with that order and the active player. `hypothetical on` permits edited puzzles with a defined cyclic order that skips completed players. Intermediate grid edits may temporarily be inconsistent; correct them before analyzing or saving. `next` explicitly advances after editing a completed turn in the grid. Editing does not automatically commit a turn.

Other commands include `name 2 Anna`, `before`, `finished`, `new 4`, `objective shared`, `objective strict`, `objective score`, `method mcts`, `time 5000`, `samples 20000`, `model greedy 2`, `save game.json`, and `load game.json`. Undo/redo covers position and analysis-setting edits. Escape cancels analysis; changes invalidate old advice. Quit with `Q`; save explicitly first.

## CLI

```sh
cargo run --release -- analyze examples/lead.json --method exact
cargo run --release -- analyze examples/trail.json --method exact --json
cargo run --release -- analyze examples/middle.json --time-ms 5000
cargo run --release -- analyze examples/middle.json --method mcts --time-ms 5000 --simulations 100000 --max-nodes 200000 --max-depth 3
cargo run --release -- analyze examples/middle.json --method rollout --simulations 10000 --seed 42
cargo run --release -- validate examples/middle.json
cargo run --release -- new --players 4 --example middle --output game.json
```

Explicit `--simulations` disables the wall-clock limit unless `--time-ms` is also passed, making runs reproducible. JSON and CLI player indices start at **0**. `--perspective 1` analyzes player 2. On someone else's turn the engine forecasts the perspective player's outcome and gives no action for them. Change the perspective to obtain advice for the active player.

The sample lead/trail positions demonstrate why the objective matters: with `6 6 6 6 2` and Chance left, taking 26 guarantees victory against 25, whereas rerolling the 2 is best against 29. Maximizing expected score instead prefers rerolling the 2 in both positions.

## Computer policies

| Preset | Decision policy |
| --- | --- |
| Easy | Greedy: scores immediately |
| Standard | Legacy category opportunity policy |
| Strong | Continuation-v2 sheet-value policy |
| Custom search | Bounded MCTS using continuation-v2; strength uncalibrated |

Adjacent presets passed a held-out evaluation with 1,000 paired seeds each, replayed with swapped seats (2,000 matches per comparison). Standard’s mean score advantage over Easy was 111.35 points; Strong’s over Standard was 16.30 points. Both win-credit confidence intervals were above parity. These are relative results among these policies, not claims of optimal play or strength against humans. [Evaluation details](docs/verification.md) include seeds, intervals, and the reproduction command.

Custom search exposes time, simulations, depth, and node limits in setup, starting at two seconds / 20,000 simulations with conservative advice enabled. More computation is not guaranteed to improve playing strength. Coaching follows the active human and models the computer’s declared baseline; for Custom search, it explicitly identifies that model as an approximation. Desktop computer games use bundled continuation evaluation for both decisions and coaching. Advisor budgets and computer budgets are separate.

Save/load preserves the computer policy, budgets, pause/fast-play settings, current dice, and actual-game RNG position. Loading a paused computer turn waits for Resume computer. Pending decisions are recomputed after load; recorded redo outcomes are restored without rolling again.

## What the result means

The default objective is expected share of first place: an outright win is 1, a two-way tie is 1/2, and a loss is 0. Outright wins and tied-first probabilities are also reported separately. Strict-first and expected-score objectives are available.

- `exact_under_model`: all relevant branches were enumerated, within floating-point precision, against the declared opponent policies.
- `estimated`: full-game Monte Carlo estimates, using a fixed continuation policy or a frozen MCTS policy.
- `incomplete`: there is not yet a complete comparison. Bounded CLI/TUI analysis issues no best action; continuous coaching can show an explicitly provisional baseline with insufficient confidence while validation develops.

For bounded CLI/TUI analysis, `auto` attempts exact search when at most three categories remain across the entire table, within one quarter of its time budget, then falls back to MCTS. `exact` never silently returns an approximation. `rollout` compares every legal next action followed by fixed policies. `mcts` spends up to half its budget learning future decisions and then evaluates all root actions on independent simulations of the frozen policy.

The default `opportunity` policy is now **continuation_v2**: a bundled, offline-fitted sheet-value model plus exact within-turn decision-making across all categories. The last two open rows use exact expected-score continuation; an optional solitaire cache extends exact coverage. The opening `1 1 2 5 5` baseline keeps the fives without a special-case rule. This is not a claim of optimal human or computer play. `greedy` scores immediately and is deliberately weaker. Use `model opportunity 2`, `model legacy 2`, or `model greedy 2` in the TUI for per-player models. JSON uses `legacy_opportunity`; CLI accepts `--policy legacy-opportunity`.

Validation first covers every action, then concentrates on contenders, upper bounds, the baseline, and rotating exploration. Reports show the **suggestion, paired sampled leader, baseline, confidence, selection reason, and paired estimated gain** separately. **Conservative advice is enabled by default**: baseline is retained when improvement is unresolved, with an explicit provisional-baseline explanation—not a claim that baseline is best. This default was retained after low-budget sampled-leader play regressed in full-game verification. To opt into the highest paired sampled estimate despite uncertainty, disable **Conservative advice** in the GUI, use TUI `advice sampled`, or CLI `--sampled-advice`. `advice conservative` / `--conservative-advice` restores the default. With fewer than eight samples for any action, either mode uses a clearly labeled provisional baseline.

Action intervals and paired-improvement intervals each use simultaneous, time-uniform 95% Hoeffding bounds under frozen policies. They are conservative, often overlap, and do not certify global optimality or human-model accuracy. Under-sampled future tree decisions retain their baseline. More samples reduce sampling error, not model bias. GUI coaching defaults to fixed-policy rollouts after a short exact attempt for small endgames. It retains unfinished simulations, paired rounds, and completed evidence across pauses. Selecting MCTS in Settings trains for at most 500 ms or 2,000 completed games, then freezes the policy and continues independent validation. Switching Limited to Continuous extends the same search; changing a model or position starts a new one. Explicit Exact makes one bounded attempt and stops, even if incomplete.

To reproduce or customize the compact continuation model:

```sh
cargo run --release -- train-baseline --games 5000 --iterations 2 --seed 42 --output continuation-model.json
cargo run --release -- analyze examples/middle.json --baseline-model continuation-model.json
```

The GUI offers a model-path field; TUI `baseline-model path.json` selects one and `baseline-model bundled` restores the included model. Training is optional and never runs on startup. See [solver details](docs/solver.md) for the model's independence assumptions and limits.

## Optional expected-score table

```sh
cargo run --release -- precompute --position examples/trail.json --output solitaire-cache.json
cargo run --release -- analyze examples/middle.json --cache solitaire-cache.json
cargo run --release -- precompute --time-ms 10000 --max-states 100000
```

Without `--position`, precomputation starts from a blank single-player sheet. It can be expensive. Only fully solved entries are saved; running again resumes the table. The CLI prints whether the requested root was actually solved. A partial table can still accelerate/improve covered policy states. Analysis ignores corrupt/incompatible caches with a note, while precompute refuses to overwrite one silently. Cache files carry a rule version, algorithm version and checksum. There is no whole-game multiplayer table.
